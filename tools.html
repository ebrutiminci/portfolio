Drawing rules a machine can followSketchUp and AutoCAD tools for an architecture studio

I was turning a prison cell into a hostel room, in six design variants. Drawing each one by hand took hours, so I wrote down the studio's drawing rules and built tools that follow them.

3–4 hours → 25–30 minutes. One variant's plan and sections, by hand and with the tools.

PlanResearchSynthesizeDesignBuild

Problem

Hours of the same clicks

SketchUp's own 2D export meant setting up a section plane and a camera for every variant, then fixing layers and line weights by hand in AutoCAD. Six variants turned that into hours of repetition. The AI render plugins I found either needed SketchUp 2024 or later, or cost money with no sign they would keep the geometry.

The manual process, per variant

  • 1 · Set up. Place a section plane and a camera in SketchUp for the plan, then again for each section.
  • 2 · Export. Export each view as a separate 2D DWG.
  • 3 · Clean up. Open in AutoCAD, move every line to the right layer, fix line weights, redraw what came out as broken segments.
  • 4 · Repeat. Three drawings × six variants. About 3–4 hours for one variant.

The people I was designing for were the architects in the studio, me included. They don't want a new program to learn. They want their drawings done right, in their own files, on their own layers.

Key decision

Rules first, tools second

Before building anything, I wrote the drawing standard as rules that a person and an AI can both check: every real piece is one polyline, no double lines, no line ends in mid-air, a steel profile is one closed outline (an IPE beam has exactly 12 vertices). Hatching only on metal, timber stays empty.

How I worked

  • 1 · Interview first. Claude asked me one multiple-choice question at a time until every rule was decided. No code before that.
  • 2 · Build the loop. Claude writes a Ruby script, runs it in SketchUp on my computer, then reads a check report and saved iso, top and front views. If something is wrong it undoes and retries, at most three times.
  • 3 · Shared helpers. Panels, walls, openings, joints, components and the check report live in one library, so every script stays short and follows the same rules.
  • 4 · Test on a real model, fix the same day. Naming worked, but parts also had to roll up into units people think in: "A - Bench unit", "B - Table + chairs", "C - Room". I added assemblies (and sub-assemblies, C › C1 › C1.1), and the report now flags parts outside any assembly. Library v1.1 updates the old copy on its own.

For modelling I did the same. A structured interview, one multiple-choice question at a time, fixed every decision: centimetres, one solid per part, groups for single parts and components for repeated ones, tags by element type, real panel thickness and real joints. That became a /sketchup command that models to my rules, checks its own result against a report and three saved views, and retries at most three times. It took one day, two short sessions, on 3 November.

Build

One click from model to sheet

Plan & Section Export cuts a plan at any height, a long section and a cross section, adds level marks (±0.00, +0.19) and writes one DXF on the studio's layers: CUT 0.35, VIEW 0.09, ABOVE 0.09 dashed grey, LEVELS, TEXT. Every piece is one closed polyline, the same rule as above. I built it in about 45 minutes on 8 October 2026 and went through six versions while using it on the real project.

How I worked: build, use, fix

  • 0.1 · The core. Select a group; the tool computes the cut faces and finds visible edges with ray tests, so lines behind other things are never drawn.
  • The files wouldn't open. On Windows every line ending was doubled. The DXF is now written byte by byte.
  • Three files was two too many. All drawings now go into one DXF, side by side with titles.
  • Plans had no levels. The mark sat at the centre of a surface, under the stair. It now goes on a point of the surface you can see.
  • AutoCAD 2000 with line weights wouldn't open. I based the file skeleton on a template from a DXF library, and it passed that library's audit.
  • Hatching: added, then removed. It made the file harder to open, and nobody needed it.

Result. One variant's plan and two sections in 25–30 minutes instead of 3–4 hours, on the studio's own layers.

Design for trust

AI renders that show what they cost

Wiro Render sends the current SketchUp view to an AI image model and saves the result next to the model. I built it in about 45 minutes, ten versions from 0.1 to 0.10, each one fixing something that happened while I used it.

How I worked: each problem, then the fix

  • The AI copied objects from my reference photos. The reference now never reaches the render model. A vision model first describes only its materials, colours and light, and the renderer gets that text.
  • The reference wasn't read at all. The model I picked didn't accept images. The plugin now finds the image models on Wiro and tries them in turn.
  • The spend counter stayed empty. When Wiro doesn't report a cost, it counts the list price and says so.
  • The batch bug. A SketchUp timer started the same batch about 20 times in parallel. I lost $3–4 in one afternoon without one usable render. Timers now stop themselves, only one job runs at a time, every scene is checked before it is sent, and the price is shown before any batch.

Toolbox

Small tools for real annoyances

Around the two main tools grew a toolbox of five SketchUp extensions and nine AutoCAD commands, each one for a problem I hit in a real drawing.

  • Clean Lines. Removes stray edges, lines that split flat faces, and overlapping faces.
  • Wood Lattice. A parametric slat panel; new slats appear when you scale it instead of stretching.
  • Corrugated Cardboard. Draws exhibition boards that snap to real 1, 2 or 3-layer thickness. I removed a convert tool that broke the next clicks, and gave the P key back to normal Push/Pull so people's habits still work.
  • AutoCAD commands. Flag open polylines in red, delete a vertex with a double-click, label slats, dimension rectangles, crop a sheet to a boundary, draw a standard hinge detail.

How I worked: the door detail

  • 1 · Start from what exists. Only an elevation and a half-finished axonometric. I modelled the frame, slats and hinges in Python from the elevation's dimensions.
  • 2 · Draw it, don't trace it. A small isometric script removes hidden faces; an AutoLISP routine draws the result straight into AutoCAD, the leaf pulled 120 cm forward.
  • 3 · Match the set. I read the sheet next to it and copied its language: one hatch per part at 80, 70 and 50% transparency, dashed assembly lines, labels 1, 2, 3, N1, hinge spacing 25 / 97.6 / 97.6 / 25.
  • 4 · Feedback rounds. 1:10 didn't fit the sheet, so 1:20. The hinge was redrawn twice, ending on the office's own cylindrical hinge. When I moved parts by hand, one step drew into the wrong area and deleted five surfaces; it was caught and restored.

Result. An almost finished sheet in about two days (7–8 Oct 2026). Still open: the hinges need updating to the correct hinge drawing.

General notes

What I learned

A tool that spends money needs a lock from day one. Test paid APIs with the cheapest settings first, and never let a job start twice.

Remove features that work if people don't use them. Hatching made the DXF harder to open, so it went. Batch rendering was fixed, but single renders were what I actually used.

Real use changes the structure. The first real model showed that naming worked but parts also had to roll up into units people think in, like a bench or a table and chair set. I added assemblies the same day.

An AI that draws must re-read before it changes anything. While I moved parts by hand, an automated step drew into the wrong area and deleted five surfaces. It was caught and restored, and now every step reads the sheet again first.
